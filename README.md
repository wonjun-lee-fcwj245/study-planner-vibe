# Study Planner — 프로세스 기반 바이브코딩 실험

> 본 저장소는 "프로세스에 입각한 바이브코딩의 효과"를 분석하기 위한 과제 산출물
> 학습 플래너(Study Planner)를 실험 대상으로 삼아, 요구사항 분석부터 품질 관리까지
> 소프트웨어 프로세스를 적용하면서 바이브코딩으로 구현한 전 과정을 기록

## 🎯 프로젝트 개요

- **목적**: 바이브코딩(Vibe Coding)에 SW 프로세스를 적용했을 때의 효과 측정 및 분석
- **산출물**: 학습 플래너 웹 애플리케이션 + 프로세스 적용 분석 보고서(PDF)
- **기간**: 19일 
- **방법론**: 반복적/점진적 개발 (3 iterations) + 단계별 산출물 관리

## 📁 저장소 구조

```
study-planner-vibe/
├── README.md                    # 본 문서
├── docs/
│   ├── requirements/            # 요구사항 명세서 (SRS, 유스케이스)
│   ├── design/                  # 아키텍처, 와이어프레임, ADR
│   ├── iterations/              # 이터레이션별 계획과 결과
│   ├── discussions/             # 일일 토의 기록 (자문자답, AI 토론 로그)
│   ├── prompts/                 # 바이브코딩에 사용한 프롬프트와 응답 로그
│   └── retrospectives/          # 이터레이션별 회고 (KPT)
├── src/                         # 학습 플래너 소스 코드
├── tests/                       # 테스트 케이스 및 결과
└── assets/                      # 스크린샷, 다이어그램 등
```

## 🔄 적용 프로세스

본 프로젝트는 **반복적 개발 모델**을 기반으로 다음 단계를 따름

| Phase | 기간 | 주요 활동 |
|-------|------|----------|
| 1. 도입·요구사항 | Day 1~4 | 비전 정의, SRS 작성, 우선순위 결정 |
| 2. 정련·설계 | Day 5~7 | 아키텍처 결정(ADR), 와이어프레임, 프롬프트 전략 |
| 3. 이터레이션 1 (MVP) | Day 8~11 | 핵심 기능 바이브코딩, v0.1 릴리스 |
| 4. 이터레이션 2 (확장) | Day 12~15 | 기능 추가, UI 다듬기, v0.2 릴리스 |
| 5. 이터레이션 3·품질 | Day 16~18 | 테스트, 리팩토링, v1.0 릴리스 |
| 6. 전환·보고 | Day 19 | 분석 보고서 작성 및 제출 |

## 🏷️ 커밋 메시지 규칙

각 커밋은 어느 프로세스 단계에 속하는지 prefix로 표시함

- `[REQ]` 요구사항 관련 (분석, 명세, 우선순위)
- `[DESIGN]` 설계 관련 (아키텍처, UI, ADR)
- `[CODE]` 구현 (바이브코딩 결과 포함)
- `[TEST]` 테스트 작성·실행
- `[DOC]` 문서화
- `[REFACTOR]` 리팩토링
- `[RETRO]` 회고
- `[CHORE]` 설정, 폴더 정리 등
