재사례. 카테고리가 안정화되고 있음.

**현재까지 자발 추가 패턴**:

|------|------|---------|

→ 보고서 6.3절 핵심 정량 데이터.

### 2. 회귀 체크가 익숙해지면서 시간 단축
T1(매일 회귀 체크)가 Day 12 = 3분, Day 13 = 2분. 익숙해지면서 줄어드는 추세.
이터레이션 종료까지 1~2분 안착 예상. 부담 없는 일과로 자리잡음.

### 3. renderTaskList → renderAll 패턴
Day 12부터 등장한 패턴: 데이터 변경 시 단일 영역(taskList)만 갱신하지 않고 전체(progress + filter
+ taskList)를 갱신. 성능 면에선 살짝 비효율이지만, 일관성 면에서 압도적.

**작은 통찰**: 이게 React의 함수형 컴포넌트 사고와 비슷하다. ADR-002(Vanilla JS)인데도
"전체 다시 그리기" 패턴이 자연스럽게 형성됨. 데이터 → UI 단방향 흐름.
→ 보고서 6.2절(설계 단계 교훈) "프레임워크 없이도 유사 패턴이 형성된다" 사례.
