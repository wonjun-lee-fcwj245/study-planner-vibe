### 자발 추가 (정형 항목)

**자발 추가 #1**: 막대에 `transition: height 0.3s ease`
- **상황**: 프롬프트에 트랜지션 명시 없음. LLM이 자발적으로 height 변경 시 부드러운 애니메이션 추가.
- **SRS 정합성**: NFR-02(반영 200ms) — 300ms는 한도 약간 초과지만 시각 전환만 해당, 데이터 반영은 즉시.
- **분류**: NFR 정합성 경계 — Day 9 transition(200ms)보다 약간 김.
- **판단**: 채택. 사용자가 차트 변화를 자연스럽게 인지하도록 함. 데이터 반영 자체는 즉시.

**자발 추가 #2**: `min-height: 2px`
- **상황**: 0% 막대도 최소 흔적이 남도록. 그러나 height: 0%일 때는 안 보이는 게 의도(검증 기준 3).
- **SRS 정합성**: 직접 정합 없음. UX 보조.
- **분류**: "UX 개선" — Day 12 필터 카운트, Day 13 분수와 동일 카테고리.
- **판단**: 채택. height 0%일 때는 어차피 display 안 됨, 안전 가드.

## 교훈

### 1. 의도적 어려움이 첫 시도에 통과한 흥미로운 결과
어제 회고에서 "FR-04는 어려워서 누락 → FR-09도 비슷할 것"이라 예상. 그러나 FR-09는 첫 시도에 통과.
**가설 수정 필요**: "LLM의 누락은 작업 난이도가 아니라 검증 기준 명시성의 함수다."

비교:
- **FR-04** (Day 10): 검증 기준 6개 중 엣지 케이스가 **본문에 섞여** 있음 → 2개 누락
- **FR-09** (Day 14): 검증 기준 8개 중 엣지 케이스가 **각 번호로 분리 명시** → 0개 누락

차이: FR-09에서는 검증 기준을 번호로 명시하고 각 항목을 "관찰 가능한 동작"으로 적었다.
**프롬프트 구조 변경(어제 회고의 학습)이 LLM 누락률을 낮춘 직접 증거.**
→ 보고서 6.3절 핵심 사례. "검증 기준의 형식이 LLM 정확도에 영향"

### 2. ADR-003이 자발 라이브러리 추천을 차단
LLM이 차트를 만들 때 자발적으로 "Chart.js를 추천드립니다" 같은 제안을 자주 한다.
오늘 그게 발생하지 않았다 — ADR-003을 프롬프트 맥락에 명시했기 때문.
**ADR이 사전 차단 기능을 했다는 직접 증거.** Day 5 FWC-001(자동 분배 거절)과 같은 방어 패턴.
→ 보고서 6.2절(설계 단계 교훈) "ADR의 사전 차단 효과" 사례.

### 3. 헬퍼 함수 재사용성
어제 Day 13에서 `isSameDay`를 별도 함수로 분리한 결정이 오늘 즉시 보상됨.
재사용 없이 인라인 처리했다면 같은 로직을 두 곳에 적었을 것이고, FR-09 구현 시 수정 부담 증가.
**Day 13 토의의 가설("FR-09에서 재사용 가능성")이 정확히 실현.**
→ 보고서 6.2절 "설계 결정의 단기 검증" 사례.

### 4. 가설 진화: "자발 추가는 작업 난이도에 반비례"가 부분 수정
FR-09는 의도적 어려움인데 자발 추가가 2건. 이전 가설(Day 10)은 "어려운 작업에서 자발 추가 감소".
**부분 수정**: "자발 추가는 작업 난이도에 반비례 + 검증 기준 명시성이 충분하면 어려운 작업에서도 자발 추가 발생."
복잡도 증가의 일종이지만, 보고서 분석의 깊이가 깊어지는 신호.
