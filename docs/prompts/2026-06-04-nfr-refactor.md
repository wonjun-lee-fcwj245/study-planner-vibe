### 의도적 모호함에 대한 LLM 결정 — Phase 4 가설 검증

**검증 기준 6**: "코드 중복이 발견되면 통합할지 분리 유지할지는 LLM 판단"

**LLM의 결정**:
- 두 개의 keydown 리스너 → 하나로 **통합** (응집도 개선)
- 그러나 `saveTasks/loadTasks`의 try-catch 중복은 **분리 유지** (각 함수의 책임 명확)
- 렌더링 함수들(`renderProgressCard`, `renderWeeklyChart`, `renderSubjectStats`)도 **분리 유지**

**LLM의 명시 근거**: "각 함수의 책임이 명확하고, 변경 시 영향 범위를 최소화하기 위함."

## 교훈

### 1. **Phase 4 가설 수정 — 단일 원칙이 아니라 맥락별 원칙**
어제 가설("LLM은 단일 일관 원칙으로 모호함을 채운다")이 오늘 부분 수정.
**LLM은 맥락(사용자 데이터 / 코드 구조)에 따라 적절한 원칙을 선택한다.**
이는 가설의 진화이자 정밀화 — Phase 4를 더 정확한 형태로 만듦.

만약 어제의 단순한 가설을 그대로 두면 보고서가 약해진다.
오늘의 검증과 수정이 가설을 강력하게 만든다.
**가설은 검증을 거치면서 더 정확해진다 — 본 과제의 핵심 메타 메시지.**
→ 보고서 1.3절(가설), 7.1절(검증) **Phase 4 정밀화 사례**.

### 2. 자발 추가는 새 기능 작업에서 활발, 리팩토링에서 감소
오늘 자발 추가 2건 vs 어제(새 기능) 4건. 가설 강화:
**"LLM 자발 추가는 새로움이 있어야 발생. 리팩토링은 기존 패턴 유지이므로 여백이 적음."**
이는 Day 15 FR-10(패턴 재사용, 자발 추가 0건)의 관찰과 일관.
→ 보고서 6.3절 "자발 추가의 발생 조건" 정밀화.

### 3. 원칙 3(단일 책임)의 의도적 위배는 정합 가능
오늘 NFR-04, 05, 07을 한 프롬프트에 묶음. 원칙 3 위배처럼 보이지만:
- 세 NFR이 결합도 매우 높음 (주석 다는 김에 접근성도, 그 김에 호환성)
- 별도 사이클로 분리하면 같은 코드를 3번 읽어야 함
- 회귀 위험을 한 번에 검증 가능
**원칙은 절대 규칙이 아니라 합리적 기본값.** 더 좋은 이유가 있으면 의식적으로 위배 가능.
→ 보고서 6.3절(구현 단계) "프롬프트 원칙의 합리적 위배" 사례.

### 4. NFR-07 (주석 100%) 달성
모든 함수 JSDoc + 모든 상수 의미 주석 + 핵심 결정 지점 인라인 주석.
이로써 본 과제의 메타 NFR 검증 1개 더 통과.

### 5. 안티 패턴 발생: 0건
원칙 3 의도적 위배는 안티 패턴이 아님 — 의식적 결정.

### 6. NFR-05 브라우저 호환성 — LLM은 명세까지만, 실제 테스트는 본인 책임
LLM이 호환성 명세는 만들었지만 실제 Chrome/Firefox/Edge 테스트는 본인이 별도 수행.
**자동화 불가능한 검증은 명시적으로 사용자 책임으로 분리.** 본 과제 분석에서 자주 보이는 패턴.
→ 보고서 6.4절 "LLM의 책임 한계 명시" 사례.
