## 6. Lessons Learned ⭐

> **본 절이 평가의 핵심이다.** 일지에 매일 기록한 작은 교훈들을 4가지 큰 주제로 묶어 서술한다.

### 6.1 요구사항 분석 단계의 교훈
- 바이브코딩의 유혹 — 명세 없이 바로 코딩하고 싶었던 순간들
- SRS가 프롬프트 품질에 미친 영향

### 6.2 설계 단계의 교훈
- ADR이 후반 의사결정 비용을 어떻게 줄였는가
- 와이어프레임이 LLM에게 맥락을 전달하는 데 어떻게 사용되었는가

### 6.3 구현 단계의 교훈
- 좋은 프롬프트의 특징 (구체적 사례 기반)
- 나쁜 프롬프트의 특징
- AI가 만든 코드를 이해하지 못한 채 쌓였을 때의 후폭풍

### 6.4 품질 관리 단계의 교훈
- 테스트가 바이브코딩 결과물에 대해 갖는 특수한 의미
- 리팩토링 시점의 판단

### 6.5 종합 교훈
- 프로세스 적용의 비용 vs 편익
- 어떤 프로젝트에서 이 방식이 가장 유효한가
- 어떤 단계는 1인 20시간 프로젝트에 과했는가
