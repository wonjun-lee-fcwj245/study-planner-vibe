## 오늘 고민한 문제 (What I struggled with)

### 고민 1: ADR-003을 작성할지, 그냥 코드만 짤지
**상황**:
"라이브러리 안 쓴다"는 사실은 이미 ADR-002에 있다. 별도 ADR을 또 만드는 게 중복 아닌가?

**선택지**:
- A. ADR-003 작성 — 거절의 추적성 확보, 시간 12분 소요
- B. 일지에만 한 줄 — 빠름, 추적성 약함
- C. ADR-002에 추가 항목 — 일관성, 그러나 ADR-002의 범위 확대

**결정과 이유**:
A 선택. 핵심 근거 3가지.

(1) **ADR-002는 "초기 선택"이고, ADR-003은 "구체적 거절"이다.** Vanilla JS를 처음에 선택한
결정과, 차트가 등장한 시점에 "라이브러리 도입 유혹을 거절"한 결정은 다른 의사결정이다.
ADR-002 작성 시점엔 차트가 등장하기 전이었다.

(2) **거절의 일자가 다르다.** ADR-002는 Day 4, ADR-003은 Day 14. 거절이 발생한 맥락(차트 등장)을
별도 ADR로 보존하는 게 의사결정 이력의 정확성을 높인다.

(3) **Day 5 FWC-001과의 일관성.** 자동 분배 기능 거절도 별도 문서로 만들었다. ADR-003도 같은 패턴 —
**"거절도 결정이고, 결정은 문서화한다."**

ADR 작성 12분 투자가 보고서에서 가치 있는 사례를 만들었다. 본 과제 분석에서 ADR-003은 "ADR이 라이브러리 자발 추가를 차단한 직접 증거"로 인용된다.

### 고민 2: 막대 차트의 height % 계산 방식
**상황**:
모든 막대를 그 주의 최댓값 대비 비율로 할지, 절대값으로 할지.

**선택지**:
- A. 최댓값 대비 비율 — 작은 값도 잘 보임, 그러나 의미 왜곡 가능
- B. 절대값 (max=10 가정) — 의미 안정적, 작은 값 안 보임
- C. 두 모드 토글 — 오버 엔지니어링

**결정과 이유**:
A 선택. **본 버전의 사용 맥락에서 "추이"가 "절대량"보다 중요**하기 때문이다.
페르소나 1의 사용 시나리오: "지난 일주일 어떻게 했나 한눈에 본다" — 추이 파악이 목적.
최댓값 정규화가 추이를 가장 명확하게 시각화한다.

LLM이 자발적으로 max 정규화를 선택한 것도 같은 직관. 명시하지 않았는데 정확한 선택.

### 고민 3: 오늘 막대 강조 색상
**상황**:
검증 기준 6: "오늘 막대는 시각적으로 강조". 어떤 색?

**선택지**:
- A. 빨강 강조 — 강력하지만 부정적 느낌
- B. 검정 — 차분, 다른 강조와 톤 통일
- C. 다른 파랑 톤 — 막대 색과 같아 차이가 약함

**결정과 이유**:
B 선택. LLM이 `#1d1d1f` (검정)를 선택. 이는 **필터 활성 칩의 색과 정확히 같다.**
앱 전체에서 "현재 활성"을 검정으로 표현하는 일관성. 와이어프레임에 명시 안 됐는데도 LLM이 시각적 일관성을 자발적으로 유지.

이게 자발 추가의 **새 패턴**: "디자인 시스템 일관성 자동 유지."
이전 자발 추가는 NFR 정합 / UX 개선 / 엣지 케이스 처리였는데, 오늘 새 카테고리 추가.

## 오늘의 작은 lessons learned

- [x] 프롬프트 품질과 산출물 품질의 관계 — **검증 기준 형식이 LLM 정확도에 영향**이라는 신규 통찰
- [x] 프로세스 단계를 건너뛰고 싶은 유혹과 그 결과 — ADR-003 작성 결정
- [x] AI 코드를 이해하지 못한 채 쌓일 때의 리스크 — 마커 누적 0건 (14일째)
- [x] 회고가 다음 사이클에 미친 영향 — Day 11 T3가 오늘 직접 적용됨

**오늘의 교훈 네 가지**:

첫째, **LLM 누락은 작업 난이도가 아니라 검증 기준 명시성의 함수다 (가설 정밀화).**
어제까지 가설은 "어려운 작업에서 누락 증가"였다. 오늘 FR-09(어려움 + 명시적 검증 기준) 사례가
가설을 정밀화했다 — **명시성이 충분하면 어려운 작업에서도 누락이 안 일어난다.**
이는 Day 10에서 도출한 핵심 명제("프로세스는 누락을 막지 못한다")의 부분 수정 — **명시 형식이 충분하면 막을 수도 있다.**
→ 보고서 1.3절(가설) 정밀화, 7.1절(검증) **결정적 업그레이드**.

둘째, **거절도 ADR이다. 거절의 명문화가 미래의 자발 추가를 차단한다.**
ADR-003 작성으로 LLM의 Chart.js 자발 추천이 발생하지 않았다. 이는 Day 5 FWC-001(자동 분배 거절 문서)와
같은 방어 패턴의 두 번째 사례. **프로세스는 결정만 정의하는 게 아니라 거절을 추적한다.**
→ 보고서 6.2절(설계 단계 교훈) "거절의 추적성" 핵심 사례.

셋째, **자발 추가의 4번째 카테고리 발견 — "디자인 시스템 일관성 자동 유지".**
오늘 막대 강조 색이 필터 활성 칩과 동일한 검정으로 자발 선택. 와이어프레임에 명시 안 됐는데 LLM이
시각적 일관성을 자발적으로 유지. 자발 추가 분류가 4개로 확장:
(a) NFR 정합 (b) UX 개선 (c) 엣지 케이스 자발 처리 (d) **디자인 시스템 일관성**
→ 보고서 6.3절(구현 단계) "LLM 자발 추가의 4가지 카테고리" 사례.

넷째, **이전 결정의 단기 검증.** Day 13에서 `isSameDay`를 별도 함수로 분리한 결정이 오늘 즉시 보상.
어제 토의 가설("FR-09에서 재사용 가능성")이 정확히 실현. **설계 결정의 가치가 다음날 검증되는 사이클이
이터레이션 후반부에 안정화됐다.**
→ 보고서 6.2절 "설계 결정의 단기 검증 사이클" 사례.
