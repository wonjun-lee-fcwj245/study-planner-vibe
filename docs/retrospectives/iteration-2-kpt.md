## 3. 가설의 진화

본 이터레이션의 가장 중요한 학술적 가치는 **가설의 정밀화 과정**이다.

### Phase 1: 광범위한 초기 가설 (Day 1)
> "프로세스 적용은 바이브코딩의 한계를 완화한다."

너무 광범위해서 검증·반증 어려움.

### Phase 2: 정밀화 1차 (Day 10 FR-04)
> "프로세스는 LLM의 누락을 막지 못한다. 그러나 누락을 즉시 발견하게 만든다."

FR-04 시도 1에서 명시한 엣지 케이스가 누락된 경험에서 도출.
검증·반증 가능해짐. 본 과제 핵심 메시지로 자리잡음.

### Phase 3: 정밀화 2차 (Day 14 FR-09)
> "**명시 형식이 충분하면 누락을 막을 수도 있다.** 검증 기준의 형식이 LLM 정확도를 결정한다."

FR-09가 의도적 어려움에도 첫 시도 통과한 경험에서 도출.
Phase 2 가설의 부분 수정 — "막지 못한다" → "형식 충분하면 막을 수도 있다."

### 가설 진화의 메커니즘

| Phase | 트리거 | 정밀도 |
|-------|--------|--------|
| 1 | 본 과제 시작 | 낮음 |
| 2 | FR-04 실패 (Day 10) | 중간 |
| 3 | FR-09 성공 (Day 14) | **높음** |

**핵심 통찰**: 가설이 **실패와 성공을 모두 거치면서** 정밀해진다.
모든 시도가 성공이었다면 Phase 2를 안 거쳤을 것이고, 모든 시도가 실패였다면 Phase 3을 안 거쳤을 것이다.
**이터레이션 1의 의도적 어려움 도입(Day 9 결정)이 Phase 3 정밀화의 전제 조건이었다.**

→ 보고서 1.3절(가설), 7.1절(검증) 핵심 흐름. 학술적 가치의 핵심.

## 4. KPT 회고

### Keep (계속할 것)

**K1. T1 매일 회귀 체크 — 5분에서 2분으로 정착**
4일 연속 적용, 회귀 0건. 시간도 단축됨 (3분 → 2분). 이터3에서도 유지.

**K2. T2 자발 추가 정형 항목 — 새 카테고리 2개 발견 가능하게 함**
이터1에선 "자발 추가 있음"으로 단순 기록했는데, T2 적용으로 4개 카테고리 분류 가능.
이터3에서도 모든 프롬프트 로그에 정형 항목 유지.

**K3. T3 의도적 어려움 도입 — 가설 정밀화의 트리거**
FR-09에 의도적 어려움(검증 기준 8개)을 도입한 게 가설 Phase 3 정밀화의 결정적 데이터.
이터3에서도 1개 FR에 의도적 어려움 도입.

**K4. ADR 작성의 일관성 — 거절도 ADR**
ADR-003(차트 라이브러리 거절)이 LLM의 Chart.js 자발 추천을 차단함. Day 5 FWC-001(자동 분배 거절)
와 같은 패턴. "거절도 결정"의 원칙을 이터3에서도 유지.

**K5. 검증 기준의 형식 — 번호별 분리 + "관찰 가능한 동작"**
FR-04(혼재 서술)와 FR-09(번호별 분리)의 결과 차이가 명확. 이터3 모든 프롬프트에서 적용.

### Problem (문제가 된 것)

**P1. FR-05 위치 부정확성 — 회고의 한계**
SRS 0.3 6.2절에서 FR-05를 이터2로 배정했으나 사실상 이터1에 포함됨. 이터1 회고에서 못 잡음.
**KPT는 거시 패턴 도구지 미시 정합성 검증 도구가 아니라는 한계.**
대응: 이터3 시작 시 SRS 재독 5분.

**P2. FR-09 막대 카운트 라벨이 영역 위로 살짝 튀어나옴**
짧은 막대 위 카운트 라벨이 차트 영역 위로 약간 올라감. 실용상 문제 없으나 완벽하진 않음.
이터3 NFR-04(접근성) 작업 시 함께 다듬을 가치.

**P3. 의도적 어려움이 가설 정밀화에는 성공했으나 "한계 발현 데이터"가 부족**
FR-09가 첫 시도 채택이라 "LLM의 누락"을 추가 관찰할 수 없었음. 본 과제는 한계 분석이 핵심인데,
이터2에선 "한계가 어떻게 막혔는가"만 봤고 "한계가 어떻게 발현되는가"를 못 봄.
이터3에서 의도적 어려움의 강도를 한 단계 올려 한계 재발현을 노릴 가치.

**P4. 자발 추가 4번째 카테고리("디자인 시스템 일관성")의 분류 기준이 모호**
"디자인 일관성"의 정의가 주관적. 다음 카테고리 후보가 등장하면 분류가 더 어려워질 가능성.
이터3에서 카테고리 정의를 더 엄격하게 다듬을 가치.

### Try (이터레이션 3에서 시도할 것)

**T1. (이터1 T1 유지) 매일 회귀 체크 2분**

**T2. (이터1 T2 유지) 자발 추가 정형 항목**

**T3. (변형) 의도적 어려움 강도 증가**
이터2의 FR-09 검증 기준(8개)으로는 한계 재발현 실패. 이터3에선 검증 기준을 **고의로 모호하게** 표현하거나
**서로 충돌하는 요구사항**을 포함시켜 한계를 발현시키는 시도. 이는 "LLM이 모순을 어떻게 처리하는가" 분석을 가능하게 함.

**T4. (이터1 T4 유지) 보고서 골격 즉시 메모**

**T5. (신규) SRS 재독 5분 — 이터3 시작 시점**
P1 대응. 이터3 작업 전 SRS 6.2절(이터레이션 배정)을 다시 읽고 정합성 확인.

**T6. (신규) 자발 추가 카테고리 정의 엄격화**
P4 대응. 이터3 종료 시점에 9건 자발 추가를 다시 분류하여 카테고리 정의를 명확히 함.
보고서 6.3절의 정량 데이터 분류 신뢰성을 확보.

## 5. 프롬프트 효과 정성 분석

### 가장 효과적이었던 프롬프트
**FR-09 첫 프롬프트** (Day 14, 약 50줄)

이유:
- 검증 기준 8개를 번호별로 분리 + "관찰 가능한 동작"으로 서술
- ADR-002와 ADR-003을 모두 명시 → LLM 자발 라이브러리 추천 0건
- Day 13의 isSameDay 헬퍼 재사용 명시 → 코드 일관성 자동 유지
- 의도적 어려움인데도 첫 시도 채택

**왜 잘 작동했는가**: 형식 + 맥락 + 헬퍼 재사용 + ADR 인용의 4중 가드레일이 동시에 작동.
이는 **누적된 설계 결정의 효과가 단일 프롬프트에 모두 발현된 사례**다.

### 자발 추가가 가장 풍부했던 프롬프트
**FR-06 첫 프롬프트** (Day 12, 약 35줄)

이유:
- 작업 난이도가 보통 (LLM의 인지 자원에 여유)
- 검증 기준 6개로 적당히 구체적이되, 일부 엣지 케이스를 명시하지 않음 → 자발 처리 여지

**자발 추가**: 필터 카운트 + 필터 자동 복귀 (2건).
**가설 강화**: "LLM 자발 추가는 작업 난이도가 보통이고, 검증 기준이 일부 여백을 남길 때 가장 활발."
