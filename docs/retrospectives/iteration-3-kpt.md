
### 가설 진화의 메커니즘 분석

| Phase | 트리거 | 진화 방향 |
|-------|--------|----------|
| 1 → 2 | **실패** (FR-04 누락) | 광범위 → 정밀 |
| 2 → 3 | **성공** (FR-09 의도적 어려움 통과) | 정밀 → 더 정밀 |
| 3 → 4(후보) | **새 실험** (FR-11 모호함) | 새 측면 발견 |
| 4(후보) → 4(최종) | **검증** (NFR 작업) | 단순 → 정확 |

**메커니즘**: 가설은 단일 사건으로 진화하지 않는다.
- **실패**가 가설을 정밀화시키고
- **성공**이 가설을 부분 수정시키며
- **새 실험**이 새 측면을 발견하고
- **검증**이 가설을 더 정확하게 만든다

**모든 단계가 함께 작동해야 가설이 완성된다.** 이게 본 과제의 학술적 핵심 메시지.

→ 보고서 1.3절(가설), 5.2절(정성 분석), 7.1절(검증) 모두에 인용. 보고서의 메타 메시지.

## 4. KPT 회고

### Keep (계속할 것)

**K1. 의도적 모호함 도입 — 가설 검증의 핵심 도구**
Day 16 FR-11과 Day 17 NFR에서 의도적 모호함 도입이 Phase 4 가설을 만들고 정밀화했다.
명시성만으로는 발견할 수 없는 LLM의 암묵적 원칙을 드러내는 도구. 후속 연구에서도 활용 가치.

**K2. 가설 진화의 기록 — 매일 일지에 명시**
Day 10, 14, 16, 17 각 시점에 가설의 현재 형태를 일지에 기록함. 이게 5 Phase 다이어그램의 원자료.
**기록되지 않은 가설 진화는 보고서에 인용 불가.** 매일 기록의 가치.

**K3. 의도적 단일 책임 원칙 위배 — 분석 기반 결정**
Day 17 NFR 3개를 한 프롬프트로 묶음 — 결합도 분석 기반의 의식적 결정.
AP-4 안티 패턴과의 차이는 **분석의 유무**. 원칙의 성숙한 적용.

**K4. T1~T6 모든 회고 Try 항목의 실행과 측정**
이터2 회고에서 정한 T1~T6를 이터3에서 모두 적용하고 결과를 측정함.
회고가 "지난 일 기록"이 아니라 "다음 사이클의 실행 가능한 행동 계획"이라는 본 과제 명제의 완성.

### Problem (문제가 된 것)

**P1. NFR-05 (브라우저 호환성) 실제 테스트는 Chrome만**
Firefox, Edge는 명세 기반 추정. 실제 테스트는 본 과제 범위 밖으로 분리.
**LLM이 자동화할 수 없는 검증의 한계.** 본 과제 분석에 정직하게 기록.

**P2. SRS 부정확성 2건 누적 (FR-05 위치, FR-11 UC 누락)**
이터1 회고에서 잡지 못한 미시 정합성을 이터2, 3에서 발견.
**KPT는 거시 패턴 도구지 미시 검증 도구가 아니다**라는 한계의 누적 검증.

**P3. 자발 추가 (e) "코드 품질" 카테고리의 분류 경계 모호**
오늘 추가된 5번째 카테고리(호환성 명세, 리스너 통합)가 NFR 정합과 일부 겹침.
v2.0에서 카테고리를 4개로 통합할지 5개로 유지할지 재검토 필요.

**P4. 가설 진화가 본 과제 범위 안에서 Phase 4까지만 도달**
Phase 4 정밀화 이후의 검증이 더 필요한데 본 과제 종료 시점 도달.
**Phase 5는 후속 연구 과제** — 보고서 7.3절(향후 과제)에 명시.

### Try — 본 과제 종료 후의 후속 연구 시사점

본 이터레이션이 본 과제의 마지막 코딩 사이클이므로 Try는 "다음 이터레이션" 대신
"본 과제 종료 후 후속 연구의 시사점"으로 기록한다.

**TS1**. Phase 4 가설의 추가 검증 — 다른 프로젝트 / 다른 LLM에서 같은 원칙이 발현되는지
**TS2**. 자발 추가 카테고리의 일반화 가능성 — 다른 도메인에서도 5개 카테고리로 분류 가능한가
**TS3**. 의도적 어려움/모호함 도입의 방법론화 — 실험적 프롬프트 설계 가이드
**TS4**. SRS 부정확성 발견 패턴 — 미시 정합성을 잡는 별도 도구의 필요성
**TS5**. 본 과제와 비교군 (프로세스 없는 바이브코딩) 실험 — 통제 실험 설계

이는 보고서 7.3절(향후 과제) 또는 7.4절(연구 시사점)의 핵심 자료.

> **그리고 LLM은 모호한 결정을 만나면 맥락에 맞는 원칙으로 일관되게 채운다 —**
> **사용자 데이터 맥락에서는 데이터 손실 방지, 코드 구조 맥락에서는 영향 범위 최소화.**

> **가설은 실패와 성공을 모두 거치면서 정밀해진다.**
