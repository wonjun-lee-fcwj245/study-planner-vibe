# 향후 과제 후보 (Future Work Candidates)

> **목적**: 본 버전(v1.0) 범위 외로 거절했지만, 다음 버전(v2.0)에서 검토할 만한 기능 아이디어를 보존한다.
> **사용**: 보고서 7.3절(향후 과제)의 1차 자료로 사용.
> **갱신 정책**: 거절 결정이 내려질 때마다 항목 추가. 항목을 절대 삭제하지 않는다 (이력 보존).

본 문서는 "거절된 아이디어의 묘지"가 아니라 **"의식적으로 미룬 가능성의 기록"** 이다.
프로젝트 진행 중에 등장한 모든 범위 확장 유혹을 이 문서로 추적한다. 거절 자체가 사례 연구가 되며,
보고서에서 "프로세스가 어떻게 범위를 통제했는가"의 직접 증거로 인용된다.

## FWC-001: 주간 자동 분배 (Weekly Auto-distribution)

### 기본 정보
- **제안 일자**: 2026-05-23 (Day 5)
- **제안 맥락**: 와이어프레임 작성 중, 사용자의 자기-제안
- **상태**: 거절 (Rejected for v1.0)
- **재검토 후보 시점**: v2.0

### 아이디어 요약
사용자가 일주일 고정 일정(수업, 알바, 운동 등)을 시간 블록으로 입력하고,
일주일 동안 공부할 학습 항목들을 예상 소요 시간과 함께 입력하면,
시스템이 빈 시간 블록에 학습 항목을 자동으로 분배해주는 기능.

### 기술적 실현 가능성
구현 가능하다. Greedy 알고리즘 기준:
1. 요일별 빈 시간 블록 추출
2. 각 블록의 길이 계산
3. 학습 항목을 예상 시간 큰 순서로 정렬
4. 가장 적합한 빈 블록에 배치

예상 코드 분량: 100~150줄 (JS). 바이브코딩 기준 약 30~60분.

### 거절 근거 요약

| 근거 | 출처 문서 | 충돌 내용 |
|------|----------|----------|
| AI 기반 추천 배제 | 비전 문서 6장 Out of Scope | 자동 분배는 AI 추천의 한 형태 |
| 단순함 가치 | 비전 문서 4장 핵심 가치 #2 | "추가·완료·통계 3가지"의 정의 위배 |
| MoSCoW 체계 외부 | SRS 0.3 6장 | 13개 FR 어디에도 속하지 않음 |
| 페르소나 불일치 | SRS 0.3 2장 | "체계적 관리"의 주체가 시스템으로 이전됨 |

### v2.0에서 재검토 시 고려사항

만약 v2.0에서 이 기능을 도입한다면, 다음 사전 작업이 필요하다:

1. **새 페르소나 정의** — "시간 계획에 약한 학생" 또는 "학습 시간 최적화에 관심 있는 사용자"
2. **비전 재정의** — 핵심 가치에서 "단순함"의 범위 조정 또는 새 가치 추가
3. **데이터 모델 확장** — 고정 일정 객체(`Schedule`), 시간 블록 객체(`TimeBlock`) 추가
4. **알고리즘 ADR 작성** — Greedy vs 제약 만족 알고리즘 vs ML 기반 추천 비교
5. **사용자 경험 설계** — 자동 분배 결과를 사용자가 어떻게 수정·재실행하는가
6. **윤리적 고려** — 시스템 추천에 대한 사용자 의존성 증가 가능성

> 세 층에서 근거를 추출하여 결정. 본 사례는 보고서 6.1절(요구사항 분석 단계의 교훈)에

> 라는 핵심 메시지의 직접 증거로 인용된다."
