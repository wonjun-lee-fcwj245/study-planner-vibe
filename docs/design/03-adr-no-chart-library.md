# ADR-003: 차트 라이브러리 도입 거절, CSS 막대로 직접 구현

## 상태 (Status)
채택됨 (Accepted)

## 일자
2026-06-01

## 맥락 (Context)

FR-09(7일 일별 완료 항목 차트)와 FR-10(과목별 완료율 막대)을 구현해야 한다.
이는 본 과제에서 처음으로 "시각적 데이터 표현"이 등장하는 시점이다.

선택의 분기점이 명확하다.
- **옵션 A**: Chart.js, ApexCharts 등 외부 차트 라이브러리 도입
- **옵션 B**: CSS flexbox + height % 만으로 직접 막대 차트 구현

이 결정은 단순한 기술 선택이 아니다. **ADR-002(외부 라이브러리 금지)와의 정합성**이 직접
관련된다. Day 5의 와이어프레임 작성 시점에 ADR-003을 미리 만들지 않기로 결정했었는데
(Day 4 일지 고민 3 참조), 그 결정의 효력이 오늘 발휘된다.

## 검토한 대안 (Options Considered)

### 옵션 A: Chart.js (CDN으로 가져오기)

- **장점**:
  - 구현 시간 10분 미만 (몇 줄 설정으로 차트 완성)
  - 반응형, 애니메이션, 툴팁 등 기본 제공
  - 업계 표준, 풍부한 문서
- **단점**:
  - ADR-002 (외부 라이브러리 금지) 위배 — 새 ADR로 예외 처리 필요
  - 라이브러리 코드를 본인이 100% 이해 못함 (MNFR-02 약화)
  - 약 200KB 추가 다운로드 (NFR-01 로딩 2초에 영향, 다만 한계 내)
  - 본 버전의 차트 복잡도(단순 막대 7개)에 과한 도구

### 옵션 B: CSS 막대 직접 구현

- **장점**:
  - ADR-002 일관성 유지 — 외부 의존 끝까지 0개
  - 본인이 모든 코드 100% 이해 (MNFR-02 강하게 준수)
  - 코드 부담 적음 — 막대 7개의 height 계산은 단순
  - 와이어프레임 영역 C의 막대 형태가 정확히 CSS로 표현 가능
- **단점**:
  - 애니메이션, 툴팁 등 부가 기능 없음
  - 차트가 복잡해지면(예: 다중 시리즈, 곡선) 직접 구현 비용 증가
  - 약간의 코드 추가 (50~70줄 추정)

### 옵션 C: 경량 라이브러리 (Sparkline 등)

- **장점**: A보다 가벼움
- **단점**: 외부 의존이라는 본질은 A와 동일, ADR-002 위배는 그대로

## 결정 (Decision)

**옵션 B (CSS 막대 직접 구현)를 채택한다.**

### 핵심 근거 4가지

**첫째, ADR-002의 일관성 유지가 본 과제 분석에 가치 있다.**
"외부 라이브러리 끝까지 0개"라는 결정의 효력이 마지막 차트까지 이어지는 것이 본 과제 보고서의
강력한 사례가 된다. ADR이 후속 결정의 가드레일로 작동하는 핵심 증거.

**둘째, 본 버전의 차트 복잡도가 옵션 B로 충분하다.**
와이어프레임 5.2절의 영역 C 막대 7개와 영역 D의 진행 바는 모두 `height: N%` 또는 `width: N%`
한 줄로 표현 가능하다. Chart.js의 풍부한 기능은 본 버전에 불필요한 과잉.

**셋째, MNFR-02(100% 이해)를 강하게 준수한다.**
Chart.js를 쓰면 라이브러리의 옵션 객체 구조, 디폴트 동작, 자체 SVG 생성 흐름을 100% 이해하지
못한 채 사용하게 된다. 본 과제는 "바이브코딩의 한계 분석"이 목적이므로, 이해의 깊이를
일관되게 유지하는 게 분석 데이터의 품질을 보장한다.

**넷째, "거절도 ADR이다"라는 무결성.**
"라이브러리를 안 쓰기로 했다"도 의사결정이다. 이걸 별도 문서로 명문화하지 않으면 미래에
"왜 안 썼지?"라는 질문에 답할 근거가 없다. **거절 결정의 추적성을 보장한다.**

## 결과 (Consequences)

### 긍정적
- ADR-002의 효력이 본 과제 종료까지 일관되게 유지됨
- 외부 의존성 0개, 빌드 도구 0개, CDN 호출 0개의 단순함 보존
- 모든 차트 코드가 본인 이해 범위 안
- 보고서에 "ADR이 후속 결정의 가드레일로 작동" 사례 인용 가능
- FR-09, FR-10 시각화의 모든 픽셀이 명시적으로 설계됨

### 부정적 / 트레이드오프
- 차트 코드가 50~70줄 추가됨 (Chart.js라면 10줄 미만)
- 차트 애니메이션, 호버 툴팁 등 "와우 요소" 없음
- 차트 유형 변경 시(예: 라인 차트 추가) 직접 구현 부담

### 후속 영향
- **영향받는 코드**: 추후 FR-09, FR-10 구현 시 사용될 차트 렌더링 함수
- **영향받는 문서**: 와이어프레임의 차트 영역 — 변경 없음 (이미 단순 막대)
- **재검토 시점**: 다음 버전(v2.0)에서 차트 복잡도가 증가하면 (예: 시계열, 비교 차트)
  본 ADR을 부분 폐기하고 라이브러리 도입 ADR을 작성할 수 있다. 본 버전 안에서는 불필요.

### 자발 추가 가능성 차단
본 ADR을 명문화함으로써, LLM이 FR-09 구현 시 자발적으로 "Chart.js를 추천합니다" 같은
범위 부풀림을 시도해도 거절할 근거가 사전에 마련된다.
이는 Day 5의 자동 분배 기능 거절(FWC-001)과 같은 방어 패턴이다.
**ADR은 코드를 정의하는 것이 아니라 미래의 잘못된 추가를 차단한다.**
