# 와이어프레임 (Wireframes)

> **버전**: 0.1
> **작성일**: 2026-05-23
> **참조 문서**: SRS 0.3, ADR-001, ADR-002

## 1. 문서 목적

본 문서는 학습 플래너의 화면 구조와 주요 UI 요소의 배치를 정의한다.
와이어프레임은 **시각적 충실도가 아니라 정보 구조와 인터랙션 흐름**에 초점을 둔다.
실제 색상, 폰트, 픽셀 단위 디테일은 구현 단계(Day 8~)에서 결정한다.

## 2. 와이어프레임의 역할

본 프로젝트에서 와이어프레임은 다음 세 가지 목적으로 사용된다.

1. **바이브코딩 프롬프트의 시각적 맥락 제공**
   Day 8 이후 LLM에게 "이런 레이아웃으로 만들어줘"라고 첨부할 수 있는 자료
2. **요구사항과 화면 요소 간 매핑 검증**
   각 FR/UC가 화면 어디에 표현되는지 확인하여 누락 방지
3. **Day 11 이후 v0.1과의 비교 기준**
   계획한 화면과 실제 구현된 화면의 차이를 회고에서 분석

## 3. 화면 구성 개요

본 버전은 **두 개의 주 화면**으로 구성된다.

| 화면 | 이터레이션 | 관련 UC | 관련 FR |
|------|-----------|---------|--------|
| 메인 보드 | 1 (확장은 2) | UC-01, UC-02, UC-03, UC-04 | FR-01~07 |
| 통계 화면 | 2 | UC-05 | FR-08, FR-09, FR-10 |

탭이나 라우터 없이 **단일 페이지 내 영역 전환** 방식으로 처리한다 (ADR-002의 단순성 원칙 적용).

## 4. 메인 보드 와이어프레임

### 4.1 영역 구성

메인 보드는 위에서 아래로 다섯 영역으로 나뉜다.

```
┌─────────────────────────────────────────────────┐
│  [헤더] 로고 + 오늘 날짜       [오늘 진도 카드]   │  ← 영역 A: 헤더
├─────────────────────────────────────────────────┤
│  [입력] [제목 입력] [과목 셀렉트] [추가 버튼]    │  ← 영역 B: 입력
├─────────────────────────────────────────────────┤
│  [필터] 전체 · AI Agent · SW공학 · (미분류)     │  ← 영역 C: 필터
├─────────────────────────────────────────────────┤
│  ☐ Quartz Scheduler 학습 ... [삭제]            │
│  ☐ SRS 변경 이력 정리 ...    [삭제]            │
│  ☑ 유스케이스 5건 작성 ...   [삭제]   ← 완료    │  ← 영역 D: 항목 목록
│  ☑ 영어 단어 30개 복습 ...   [삭제]   ← 완료    │
│  ☐ 알고리즘 1문제 풀기 ...   [삭제]            │
├─────────────────────────────────────────────────┤
│  전체 5건 · 완료 2건 · 미완료 3건   주간 통계 → │  ← 영역 E: 푸터
└─────────────────────────────────────────────────┘
```

### 4.2 영역별 요소

#### 영역 A: 헤더 (Header)
- **좌측**: 앱 로고/제목 + 오늘 날짜 (예: "2026년 5월 23일 토요일")
- **우측**: 오늘 진도 카드 — "오늘 진도" 레이블 + 백분율 (FR-08)
- **목적**: 정체성 + 즉시 진도 확인 (페르소나 1의 "30초 이내" 요구 충족)

#### 영역 B: 입력 (Input)
- **요소**: 제목 텍스트 입력 + 과목 선택 셀렉트박스 + "추가" 버튼
- **인터랙션**: Enter 키 또는 "추가" 버튼 → UC-01 트리거
- **검증**: NFR-03(3클릭 이내 추가) 달성 — [제목 클릭] [입력] [Enter] = 0클릭(타이핑만)
- **빈 상태**: 제목이 비면 "추가" 버튼 비활성화 (UC-01 대체 흐름 4a)

#### 영역 C: 필터 (Filter)
- **요소**: 과목 칩 (pill) 형태로 가로 나열, "전체"가 기본 선택
- **인터랙션**: 칩 클릭 → FR-06 (해당 과목만 표시)
- **위치 결정 근거**: 입력 바로 아래에 두어 "지금 보고 있는 범위"를 인식하면서 추가하게 함

#### 영역 D: 항목 목록 (Task List)
- **항목 1개 구성**: 체크박스 + 제목 + 과목·시각 메타 + 삭제 버튼
- **시각 구분 (FR-07)**:
  - 미완료: 흰 배경, 검정 제목
  - 완료: 회색 배경, 취소선 제목, 흐린 색
- **정렬**: 최신 추가 항목이 상단 (UC-01 기본 흐름 5)
- **삭제 (FR-03)**: 항목 우측 휴지통 아이콘 클릭

#### 영역 E: 푸터 (Footer)
- **좌측**: 항목 통계 요약 (전체/완료/미완료)
- **우측**: 통계 화면으로 이동하는 링크

### 4.3 키보드 조작 흐름 (NFR-04)

```
Tab 1회 → 제목 입력 필드
Tab 2회 → 과목 셀렉트
Tab 3회 → 추가 버튼
Enter (필드 안) → 즉시 추가
Tab 4회~ → 각 항목 체크박스
Space (체크박스) → 완료 토글
```

## 5. 통계 화면 와이어프레임

### 5.1 영역 구성

```
┌─────────────────────────────────────────────────┐
│  [헤더] 주간 학습 통계        ← 보드로 돌아가기  │  ← 영역 A
├─────────────────────────────────────────────────┤
│  [요약 카드 3개]                                 │
│  ┌────────┐ ┌────────┐ ┌────────┐              │  ← 영역 B
│  │전체 28 │ │완료 19 │ │평균 68%│              │
│  └────────┘ └────────┘ └────────┘              │
├─────────────────────────────────────────────────┤
│  최근 7일 일별 완료 항목                         │
│  ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐ ┌──┐          │  ← 영역 C (FR-09)
│  │  │ │  │ │██│ │  │ │██│ │  │ │  │          │
│  │██│ │██│ │██│ │  │ │██│ │██│ │  │          │
│  │██│ │██│ │██│ │██│ │██│ │██│ │  │          │
│  │월│ │화│ │수│ │목│ │금│ │토│ │일│          │
├─────────────────────────────────────────────────┤
│  과목별 완료율                                   │
│  AI Agent          ████████████░░░  80%         │
│  소프트웨어공학    ███████████░░░░  75%         │  ← 영역 D (FR-10)
│  자료구조          ████████░░░░░░░  50%         │
│  영어              ████████░░░░░░░  50%         │
└─────────────────────────────────────────────────┘
```

### 5.2 영역별 요소

#### 영역 A: 헤더
- 화면 제목 + 보드로 돌아가는 링크
- 보드 ↔ 통계 간 단일 동작으로 왕복 (ADR-002의 단순성)

#### 영역 B: 요약 카드 (Summary Cards)
- 7일 전체 항목 수 / 완료 수 / 평균 완료율
- 위치 결정 근거: 디테일(차트) 전에 큰 그림(숫자) 먼저 — 페르소나 1의 "어느 과목 부족한가 빨리 확인" 요구

#### 영역 C: 일별 완료 차트 (FR-09)
- 막대 차트 7개 (월~일)
- Day 12에 차트 라이브러리 도입 시 ADR-003 작성 (현재는 미정)
- 미완료 옵션: 단순 CSS 막대로도 충분할 수 있음 — 라이브러리 도입 여부는 이터레이션 1 회고에서 결정

#### 영역 D: 과목별 완료율 (FR-10)
- 가로 진행 바 형태
- 라벨: 과목명 + 분수 + 백분율
- 과목 수가 늘어나도 가독성 유지 (스크롤 가능)

## 6. 인터랙션 시나리오

### 시나리오 1: 페르소나 1(이원준)의 아침 사용
1. 앱 진입 → 메인 보드 표시 (UC-02)
2. 헤더의 "오늘 진도 0%" 확인 → 동기 부여
3. 입력 필드에 "Quartz Scheduler 학습" 입력 → 과목 "AI Agent" 선택 → Enter (UC-01, FR-01)
4. 다음 항목 추가 (반복)
5. 학습 시작
- **목표 소요 시간**: 30초 이내 (페르소나 1의 사용 맥락)

### 시나리오 2: 학습 도중 완료 체크
1. 학습 한 단위 완료
2. 해당 항목 체크박스 클릭 (UC-03, FR-02)
3. 항목이 회색·취소선으로 바뀜 (FR-07)
4. 헤더의 "오늘 진도" 카드 즉시 갱신 (NFR-02 200ms 이내)

### 시나리오 3: 주말 회고 사용
1. 푸터의 "주간 통계 보기" 클릭 → 통계 화면 (UC-05)
2. 요약 카드로 한 주 전체 그림 파악
3. 일별 차트로 "어느 날이 부족했나" 확인
4. 과목별 바로 "어느 과목이 부족했나" 확인
- **목표 통찰**: 다음 주 계획에 반영할 인사이트 1개 이상

## 7. 의도적으로 배제한 UI 요소

다음 요소들은 본 버전 와이어프레임에 **의도적으로 포함하지 않았다**.

| 배제 요소 | 사유 |
|----------|------|
| 사이드바 / 햄버거 메뉴 | 화면이 2개뿐이라 불필요 (ADR-002의 단순성) |
| 로그인 영역 | 비전 문서의 Out of Scope |
| 알림 토스트 | 모든 변경은 즉시 시각 반영 — 별도 알림 불필요 |
| 다크 모드 토글 | FR-12 Won't 결정에 따름 |
| 데이터 내보내기 버튼 | FR-13 Won't 결정에 따름 |
| 검색 입력 | 항목 수가 적어 필터로 충분 |
| 항목 드래그 정렬 | 정렬 기준이 "최신순" 단일 — 불필요 |

이 배제 결정들은 SRS의 Won't 처리 사유와 일관성을 유지한다.
