## 2. 이터레이션 1 회고 검토 후 발견된 사항

### FR-05의 상태 재평가
SRS 0.3에서 FR-05는 "사용자는 학습 항목에 과목을 지정할 수 있다"로 정의되어 있다.
이터레이션 1의 FR-01 구현 시 `subject` 필드와 입력 UI가 이미 포함되었다.

**결론**: FR-05는 사실상 이터레이션 1에서 함께 구현됨. 별도 작업 불필요.
다만 SRS 0.3 6.2절의 이터레이션 배정을 "FR-05 = 이터레이션 2"로 적은 것이 부정확했음.
**이게 이터레이션 1 회고에서 발견됐어야 하는 사항이지만 놓쳤다.**
→ **회고가 미시 누락을 거시에서 발견하지 못한 사례.** Day 12 일지에 lessons learned로 기록.

### 회고의 Try 항목 즉시 반영
- T1 (매일 회귀 체크 5분): 오늘부터 적용. 첫 작업 전 v0.1 동작 확인.
- T2 (자발 추가 정형 항목): 프롬프트 로그 양식에 절 추가 (오늘 첫 로그부터).
- T3 (의도적 어려움 도입): FR-09에 적용 예정.
- T4 (보고서 골격 즉시 메모): 매일 마지막 5분 강제 운영.
- T5 (프롬프트 전략 v1.1 개정): 이터레이션 2 종료 시점에 일괄 반영.

## 5. 의도적 어려움 도입 계획 (FR-09)

이터레이션 1 회고의 T3 적용. FR-09 검증 기준에 다음 엣지 케이스를 의도적으로 포함:

1. 데이터 0건 시 빈 차트(또는 안내 메시지) 표시
2. 7일 중 일부 날짜에 데이터 없을 때 0으로 채우기
3. 한 날짜에 100건 이상 데이터가 있어도 차트가 깨지지 않음
4. 차트 라이브러리 도입 시 ADR-003 작성 (외부 라이브러리는 ADR이 필요 — ADR-002의 단순성과 트레이드오프)

특히 **4번이 핵심 결정점**이다. Chart.js를 도입할지, CSS 막대로 직접 구현할지 선택해야 함.
이것 자체가 이터레이션 2의 가장 큰 설계 결정이 된다.
