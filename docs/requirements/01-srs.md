# 소프트웨어 요구사항 명세서 (SRS)

## 1. 개요

### 1.1 목적
본 문서는 학습 플래너(Study Planner) 웹 애플리케이션의 기능적·비기능적 요구사항을 정의한다.
바이브코딩 시 본 문서의 요구사항 ID를 인용하여 프롬프트를 작성한다.

### 1.2 범위
- **포함**: 단일 사용자 환경의 학습 항목 관리, 진도 통계, 데이터 영속성
- **제외**: 회원 가입·로그인, 클라우드 동기화, 다중 기기, 팀 공유, 알림

### 1.3 용어 정의

| 용어 | 정의 |
|------|------|
| 학습 항목 (Task) | 사용자가 추가하는 하나의 학습 단위. 제목, 과목, 완료 여부, 생성일을 가진다. |
| 학습 세션 (Session) | 하루 동안의 학습 활동 단위. 날짜를 키로 그룹화된다. |
| 진도율 (Progress) | 특정 기간 내 생성된 학습 항목 중 완료된 비율(%). |
| 과목 (Subject) | 학습 항목을 분류하는 사용자 정의 카테고리. (예: "데이터구조", "영어") |
| 보드 (Board) | 메인 화면. 오늘의 학습 항목이 표시되는 영역. |

## 2. 사용자 페르소나

### 페르소나 1: 이원준 — 학기 중 대학생

- **나이/직업**: 26세, 컴퓨터공학과 4학년
- **사용 환경**: 평일 도서관 노트북
- **목표**:
  - 6과목의 중간고사 학습 진도를 균형 있게 관리
  - 어떤 과목을 덜 공부했는지 시각적으로 파악
  - 다양한 프로젝트를 진행하면서 필요한 여러 학습 내용을 체계적으로 관리
  - 매일 무엇을 해야 할지 빠르게 확인
- **불편 (Pain Points)**:
  - 노션에 학습 페이지를 만들었지만, 매번 페이지 진입에 클릭이 많아 결국 안 쓰게 됨
  - 종이 플래너는 진도 통계가 안 보임
  - 구글 캘린더는 "완료 체크" 개념이 약함
- **사용 맥락 (Context)**:
  - 하루 첫 사용: 아침에 오늘 할 학습 항목 확인 (소요 시간 30초 이내 기대)
  - 하루 중 사용: 학습 단위 끝낼 때마다 완료 체크
  - 주말: 한 주 진도 돌아보기 

### 페르소나 2: 박지훈 — 자격증 준비생

- **나이/직업**: 28세, 사회 초년생, 정보처리기사 준비 중
- **사용 환경**: 퇴근 후 카페 노트북, 주말 집
- **목표**:
  - 시험 D-Day까지 단원별 학습 항목을 만들고 하나씩 처리
  - 주간 학습량을 일정하게 유지
  - 가입 절차 없이 즉시 시작 가능한 가벼운 도구
- **불편**:
  - 회원 가입형 학습 앱은 일주일 쓰다가 패스워드를 잊고 그만둠
  - Excel은 추가/삭제가 번거롭고 시각적이지 않음
- **사용 맥락**:
  - 학습 시작 시: 단원명을 학습 항목으로 추가
  - 학습 중: 완료 체크
  - 주 단위: 진도율 확인하여 시험까지 페이스 조정

### 페르소나 정의 시 의도적으로 배제한 사용자

- **고등학생 / 중학생**: 학부모 통제, 알림 기능 등 추가 요구가 있어 범위 초과
- **팀 스터디 그룹**: 다중 사용자·실시간 협업 필요, 백엔드 필수, 20시간 내 불가
- **모바일 우선 사용자**: 본 버전은 데스크톱·태블릿 웹 우선

## 3. 유스케이스

### UC-01: 학습 항목 추가

| 항목 | 내용 |
|------|------|
| **주체 (Actor)** | 사용자 |
| **목적** | 오늘 할 학습 항목을 보드에 등록한다 |
| **선조건** | 앱이 정상 로드되어 메인 보드가 표시되어 있다 |

**기본 흐름**:
1. 사용자가 메인 보드의 "학습 항목 추가" 입력 필드를 클릭한다
2. 학습 항목 제목을 입력한다 (예: "Quartz Scheduler 학습")
3. 과목을 선택하거나 새로 입력한다 (예: "ai agent, 소프트웨어 공학")
4. "추가" 버튼을 클릭하거나 Enter 키를 누른다
5. 시스템이 학습 항목을 보드 최상단에 표시한다
6. 시스템이 localStorage에 항목을 저장한다
7. 입력 필드가 비워지고 다음 입력을 받을 준비를 한다

**대체 흐름**:
- 3a. 사용자가 과목을 선택하지 않으면, "(미분류)"로 자동 지정된다
- 4a. 제목이 비어 있으면, 추가 버튼이 비활성화되고 안내 메시지가 표시된다

**후조건**:
- 보드에 새 학습 항목이 표시된다
- 새로고침 후에도 항목이 유지된다

### UC-02: 오늘의 학습 항목 보기

| 항목 | 내용 |
|------|------|
| **주체** | 사용자 |
| **목적** | 오늘 처리해야 할 학습 항목을 한눈에 확인한다 |
| **선조건** | 1개 이상의 학습 항목이 등록되어 있다 |

**기본 흐름**:
1. 사용자가 앱에 진입한다
2. 시스템이 localStorage에서 학습 항목을 불러온다
3. 시스템이 메인 보드에 오늘 날짜의 학습 항목을 표시한다
4. 각 항목은 제목, 과목, 완료 체크박스를 포함한다
5. 완료된 항목은 시각적으로 구분된다 (예: 취소선, 흐린 색)

**대체 흐름**:
- 2a. 저장된 항목이 없으면, "오늘 학습할 내용을 추가해보세요" 안내가 표시된다

**후조건**: 사용자가 30초 이내에 오늘의 학습량을 파악할 수 있다

### UC-03: 학습 항목 완료 처리

| 항목 | 내용 |
|------|------|
| **주체** | 사용자 |
| **목적** | 완료한 학습 항목을 체크하여 진도를 기록한다 |
| **선조건** | 1개 이상의 학습 항목이 보드에 표시되어 있다 |

**기본 흐름**:
1. 사용자가 학습 항목의 체크박스를 클릭한다
2. 시스템이 해당 항목의 완료 상태를 토글한다 (false → true)
3. 시스템이 항목에 완료 시각을 기록한다
4. 시스템이 항목의 시각적 표시를 변경한다 (취소선 등)
5. 시스템이 localStorage에 변경 사항을 저장한다

**대체 흐름**:
- 1a. 이미 완료된 항목을 다시 클릭하면, 미완료 상태로 되돌린다 (실수 복구)

**후조건**:
- 완료 상태가 영속적으로 저장된다
- 진도율 통계(UC-05)에 즉시 반영된다

### UC-04: 학습 항목 삭제

| 항목 | 내용 |
|------|------|
| **주체** | 사용자 |
| **목적** | 잘못 입력했거나 더 이상 필요 없는 항목을 제거한다 |
| **선조건** | 1개 이상의 학습 항목이 보드에 표시되어 있다 |

**기본 흐름**:
1. 사용자가 항목 옆의 삭제 버튼을 클릭한다
2. 시스템이 삭제 확인을 요청한다 (또는 짧은 undo 기회 제공)
3. 사용자가 확인하면, 시스템이 항목을 보드에서 제거한다
4. 시스템이 localStorage에서 해당 항목을 삭제한다

**대체 흐름**:
- 2a. 사용자가 취소하면, 항목은 그대로 유지된다

**후조건**: 새로고침 후에도 해당 항목이 나타나지 않는다

### UC-05: 주간 진도 통계 확인

| 항목 | 내용 |
|------|------|
| **주체** | 사용자 |
| **목적** | 지난 7일간 학습 진도를 시각적으로 확인한다 |
| **선조건** | 최소 1일 이상의 학습 기록이 존재한다 |

**기본 흐름**:
1. 사용자가 "통계" 영역으로 이동한다
2. 시스템이 지난 7일간의 데이터를 집계한다
3. 시스템이 일별 완료/미완료 항목 수를 차트로 표시한다
4. 시스템이 과목별 완료율을 함께 표시한다

**후조건**: 사용자가 어떤 과목·어느 날 학습이 부족했는지 파악할 수 있다
